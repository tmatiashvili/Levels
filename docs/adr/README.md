# Architecture decision records

How to write one: [ADR-0001](0001-record-architecture-decisions.md) and [template.md](template.md). Numbers are never reused; a changed decision gets a new ADR that supersedes the old one. Feature specs are indexed in [../specs/README.md](../specs/README.md); owner decisions and lead's calls are listed in [../decisions-log.md](../decisions-log.md); terms are in [../glossary.md](../glossary.md).

| # | Title | Status | Decision in one line |
|---|---|---|---|
| [0001](0001-record-architecture-decisions.md) | Record architecture decisions as ADRs and features as specs | Accepted | Decisions in `docs/adr/`, buildable features in `docs/specs/`, both indexed. |
| [0002](0002-minimum-os-26.md) | Target only the 26 releases | Accepted | Deployment target iOS/iPadOS/macOS/watchOS 26.0 (owner: stays 26, not 27), Swift 6 strict concurrency, no older fallbacks. |
| [0003](0003-project-structure.md) | One Xcode project plus a local Swift package split into modules | Proposed | `Shared/` package with `LevelsModel`, `LevelsSync`, `LevelsReaders`, `LevelsUI`, `LevelsWidgetKit`; widgets never link `LevelsSync` or `LevelsReaders`; `Complications/` becomes `Widgets-Watch/`. |
| [0004](0004-cloudkit-private-database-only-sync.md) | Sync only through the CloudKit private database | Proposed | Own thin `BatterySyncService` on raw `CKDatabase` APIs, full-zone fetch, no change tokens; no CKSyncEngine, SwiftData or KVS. |
| [0005](0005-devicebattery-record-schema-and-zone.md) | One `DeviceBattery` record per battery in a custom `Levels` zone | Accepted | Record name = stable ID (accessories: UUIDv5); additive schema; `level` optional (desktop Macs); Production for every daily build, debug included; no auto-delete, "Old devices" after 30 days. |
| [0006](0006-change-notification-subscriptions.md) | One silent CKDatabaseSubscription, never trust push alone | Proposed | Subscription `levels-private-db`; fetch on push plus fallback fetches on launch, foreground, refresh, network reachable and Mac wake (15-min timer only while pushes seem missing); reporter self-reports `.pushWake` after a push; widgets read the cache only, never fetch. |
| [0007](0007-stable-device-identity.md) | Device identity in a this-device-only Keychain item | Proposed | Random UUID, not synchronizable; new ID after restore to new hardware; default name = model name, rename this device in-app. |
| [0008](0008-write-throttling-and-coalescing.md) | Write own records only on meaningful change | Proposed | State changes at once (3 s debounce), level in 5-point steps ≥ 60 s apart, 30-min heartbeat, urgent reasons (incl. user refresh) skip the 60 s gap, 10 s floor; last writer wins. |
| [0009](0009-app-group-snapshot-cache.md) | Cache the latest snapshot as one JSON file in the App Group | Proposed | `snapshot.json` written atomically under `NSFileCoordinator` via `SnapshotCache` in `LevelsModel`; widgets read it; group `group.<rdns>.levels` (iOS/iPadOS/watchOS), `<TEAMID>.<rdns>.levels` (Mac app and widget). |
| [0010](0010-battery-reader-abstraction.md) | One `BatteryReader` protocol, one implementation per platform | Proposed | `BatteryReader` / `BatteryReading` in `LevelsReaders`; notification-driven, no polling; one charging-flags mapping. |
| [0011](0011-ios-background-reporting-strategy.md) | iPhone/iPad reporting triggers | Proposed | Foreground, "Report Battery" App Intent via Shortcuts automations (primary), `BGAppRefreshTask`, push piggyback. |
| [0012](0012-watchos-reporting-strategy.md) | Watch reports straight to CloudKit | Proposed | Report on activation, background refresh and push; no WatchConnectivity; recommend a complication on the face. |
| [0013](0013-mac-distribution-and-sandbox.md) | Ship the Mac app with Developer ID and notarization | Accepted | Developer ID + notarized + provisioning profile; sandbox on for v0.1–v0.2, off for the Developer ID build at v0.3. |
| [0014](0014-mac-menu-bar-agent.md) | SwiftUI MenuBarExtra agent that starts at login | Proposed | One `LSUIElement` process, `SMAppService.mainApp` login item, urgent reports on sleep and wake; exactly two tolerant timers (30-min heartbeat, 15-min fetch only while pushes seem missing), accessory poll added at v0.3; desktop widget opens the device window. |
| [0015](0015-mac-accessory-battery-source.md) | Accessory battery sources; desktop Macs publish a battery-less record | Proposed | Magic peripherals from IOKit registry, AirPods from `system_profiler` (unsandboxed) as three records under one row; UUIDv5 IDs; desktop Mac publishes `level = nil`. |
| [0016](0016-shared-swiftui-view-layer.md) | One shared SwiftUI view layer fed by an @Observable store | Proposed | `DeviceListStore` + `Gauge`-based views in `LevelsUI`; one sort rule; colour never the only cue. |
| [0017](0017-widget-refresh-and-staleness.md) | Widgets reload on data change only; staleness planned into the timeline | Proposed | Reload only on change; self-updating age text; stale after 2 h (iPhone/iPad/Watch, charging or not), 65 min (Mac, accessories), 30 min for a Mac or accessory charging below 100 %; reload on any cached field change, at most once per 60 s. |
| [0018](0018-testing-strategy.md) | Swift Testing behind seams, platform tested by hand, local CI | Proposed | Unit tests against fakes; real-device QA specs per milestone; all daily builds on Production, experiments in a separate container; Debug `aps-environment = development`, others `production`; `scripts/test.sh` until the first TestFlight build, Xcode Cloud at the start of v0.1 if SPIKE-001 fails. |
| [0019](0019-privacy-and-data-handling.md) | Keep all data in the private DB, collect nothing, "Remove all my data" | Proposed | No third-party code or analytics; privacy manifest per target; zone delete removes everything. |
